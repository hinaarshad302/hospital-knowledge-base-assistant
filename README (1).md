# 🏥 Hospital Knowledge Base Assistant

A beginner-friendly Retrieval-Augmented Generation (RAG) chatbot that answers
questions about hospital policies, admissions, departments, emergency
procedures, and patient safety — using a **sample hospital knowledge base**.

Built as a portfolio AI/ML project demonstrating a complete RAG pipeline:
document embedding, vector search, and grounded LLM answer generation.

---

## ✨ Features

- Answers questions using only the retrieved hospital knowledge base context
- Avoids hallucination — replies with a clear "not found" message when the
  answer isn't in the knowledge base
- Displays the sources used to generate each answer
- Shows related hospital departments for each answer
- Suggests example and related follow-up questions
- Clean, professional, hospital-themed Streamlit UI
- Graceful handling of Gemini API quota (429) and other API errors
- Chat history with a "Clear Chat" option

## 🔍 How RAG Works (in this project)

1. Hospital PDF documents are split into text chunks.
2. Each chunk is converted into a vector embedding using Sentence
   Transformers.
3. Embeddings are stored in a FAISS vector index for fast similarity search.
4. When a user asks a question, it's embedded and compared against the
   stored chunks using cosine similarity (normalized embeddings).
5. The most relevant chunks (above a similarity threshold) are passed to
   Gemini as context.
6. Gemini generates an answer **grounded only in that retrieved context** —
   it does not answer from general knowledge.
7. If no relevant chunks are found, the app returns:
   > "I don't have that information in the current knowledge base."

Retrieval settings currently used:

```
TOP_K = 5
MIN_SIMILARITY = 0.30
SIMILARITY_GAP = 0.08
```

```
├── .streamlit/
│   └── secrets.toml.example

    ├── index.faiss        # not included — see Setup below
    └── metadata.pkl       # not included — see Setup below
```

> **Note:** `faiss_index/index.faiss` and `faiss_index/metadata.pkl` are
> generated by the project's indexing pipeline (PDF → chunking → embeddings
> → FAISS index) and are not included in this repository. Generate them
> yourself from the sample hospital PDFs, or upload your own pre-built
> index files into the `faiss_index/` folder before running the app.

## ⚙️ Setup Instructions

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/hospital-kb-assistant.git
cd hospital-kb-assistant
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Add your Gemini API key

Copy the example secrets file:

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```

Then open `.streamlit/secrets.toml` and add your real key:

```toml
GOOGLE_API_KEY = "your-actual-gemini-api-key"
```

> ⚠️ Never commit your real `secrets.toml` file — it's already excluded via
> `.gitignore`.

### 4. Add the FAISS index files

Place your generated `index.faiss` and `metadata.pkl` files inside the
`faiss_index/` folder.

### 5. Run the app

```bash
streamlit run app.py
```

## ⚠️ Limitations

- Uses a **sample/demo hospital knowledge base** — not official hospital
  documentation.
- Answer quality depends entirely on the quality and coverage of the
  underlying PDF documents.
- Subject to Google Gemini API rate limits and quotas.
- Not intended for real-world medical or emergency use.

---

## 🩺 Medical Disclaimer

This assistant answers using a **sample hospital knowledge base** for
demonstration purposes only. It does **not** provide medical advice,
diagnosis, or treatment. In a real emergency, always contact your local
emergency services or visit the nearest hospital immediately.
